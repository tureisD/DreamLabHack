`score_rollouts.py` replayed each saved action trace and checked its joint states. The largest replay error was **0.99 mm**, below the frozen 5 mm limit. It scored the recorded apple-height series using the frozen two-second held-lift rule. The unchanged base succeeded **0/4**; the second-account 500-step fine-tune succeeded **4/4**. This is a descriptive result for four same-distribution simulator scenes, not a real-robot reliability estimate or a statistically supported deployment decision. The first account's varied checkpoint also scored 4/4 on different seeds; these separate four-scene results do not rank the two fine-tunes.

The reproducible [builder](build_second_account_evidence.py) discovers all eight local rollouts and writes the [paired snapshot](../../../src/teach_task_coach/examples/second_account_paired_confirmation.json). `POST /api/paired-evaluations/analyze` returned `descriptive`, four usable pairs, zero evidence problems, and snapshot SHA-256 `cce2728a65038d49e671fe1cfb51e2b6f9d51762ee11d8bab3b1a11f58403cd2`. In **Statistical evaluation**, select **Analyze independent 500-step apple demo** to run the same API analysis and inspect each pair. A changed success label or missing checkpoint attempt in copies of this snapshot returned `not_evaluable`. This shows how the extension checks and explains the comparison; it did not change the model's weights or establish that the coach saved training time or money.
